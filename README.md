# 星歷儀表板

個人儀表板：記帳、待辦與行程、備忘錄、想法牆。

**線上試用 → https://huang940818-art.github.io/starcal-dashboard/**

打開就能直接玩（裡面是編出來的示範資料）。想拿來記自己的東西，
點右上角的徽章 →「清空，我要自己用」。

---

## 為什麼做這個

我自己寫了一支 iOS App 管健康、記帳、待辦。但有兩件事手機做不好：

1. **記帳只看得到「花了多少」，看不到「還剩多少」。** 沒有預算、沒有跨月趨勢、
   翻不到「上次那家店花多少」。
2. **想法沒有地方放。** 清單會強迫你先決定順序，但想法還沒成形的時候
   根本不知道哪個該排前面。

這個儀表板補的就是這兩塊，跑在電腦上。

## 有什麼

### 記帳

| | |
|---|---|
| **預算與超支** | 每個月給各分類設上限，看得到還剩多少、快超了會變色 |
| **跨月趨勢** | 近 6／12 個月或今年的收支長條圖，加一句話總結 |
| **月份切換** | 上一個月、這個月都能翻。往回會停在最早有帳目的月份 |
| **搜尋與篩選** | 關鍵字 × 收支別 × 分類 × 帳戶 × 期間，篩完的結果自己就是答案 |
| **固定 vs 彈性** | 分類標上性質，才知道真正能省的有多少 |
| **自訂分類** | 分類不寫死。寫死的分類遲早會缺一個，缺了就只能記到「其他」 |

帳戶餘額、轉帳、訂閱（週期換算成每月、下次扣款）也都有。

### 接下來（行程 ＋ 待辦）

**行程和待辦排在同一條時間線上**，因為它們是同一件事的兩個面向。
「明天要交回函」和「明天下午開會」都是明天要處理的事，分兩個分頁看，
就得自己在腦子裡合併——那正是最容易漏掉東西的地方。

刻意**不做月曆格子**：行程不密集的話，空月曆每次打開都在說「你什麼都沒有」。

### 備忘、想法牆

- **備忘**：跟待辦刻意分開。備忘沒有「完成」這個概念，硬塞進待辦只會讓待辦看起來做不完。
- **想法牆**：可以拖的便利貼。清單會強迫你先決定順序，但空間關係本身就是一種思考——
  把相關的擺一起、把還不確定的推到角落。

## 幾個設計決定

**同一份前端跑兩種模式。**
偵測得到本機 server 就用真實資料（存成檔案）；偵測不到（例如放在 GitHub Pages 上）
就切成展示模式，用內建示範資料 + `localStorage`。所以線上版打得開、可以點，
而私人資料從來不在這個 repo 裡。

**自己用的時候，資料存成 JSON 檔而不是 localStorage。**
清一次瀏覽器快取，記帳資料就沒了。而且檔案放在家目錄，別的工具才讀得到——
可以直接叫 Claude Code 幫你記一筆、算這個月的餐費。鎖在瀏覽器裡的資料誰都碰不到。

**server 預設只綁 127.0.0.1。**
記帳和備忘不該是同一個網路上誰都讀得到的東西。要在手機上看的話，
用 `--host` 指定一個私有網路（例如 Tailscale）的位址；程式會直接拒絕綁 `0.0.0.0`。

**存檔先寫暫存檔再 rename。**
中途斷電的話，舊檔還是完整的舊檔，不會變成寫到一半的壞 JSON。
每次覆蓋前留一份備份，保留最近 20 份。

**讀不出來的檔案不當成空的。**
當成空的話，畫面會顯示「你沒有任何帳目」，然後下一次存檔就把壞檔覆蓋成真的空檔。
所以讀取失敗會整頁停住並說明原因，一個字都不動。

**沒有任何相依套件。**
前端是原生 JS，圖表用 CSS 畫，圖示是手寫的 inline SVG；後端只用 Python 標準庫。
這種規模的東西拉一個圖表庫進來不划算，而且離線也要能開。

## 自己跑一份

線上版的資料存在瀏覽器裡，清快取就沒了。要長期用的話跑本機版：

```sh
git clone https://github.com/huang940818-art/starcal-dashboard.git
cd starcal-dashboard
./開.sh                    # 開 server 並打開瀏覽器
```

資料會存在 `~/星歷資料/*.json`（權限 700/600），**不在專案資料夾裡**。

```sh
python3 server.py --port 8787        # 換 port
python3 server.py --host 10.0.0.5    # 給同一個私有網路的手機看
STARCAL_DATA_DIR=/tmp/試玩 python3 server.py   # 換一個資料夾（測試用）
```

兩種模式都可以在右上角的徽章裡**匯出成一個檔案**，換裝置或備份就靠它。

## 測試

```sh
node --test 測試.mjs     # 19 條：算術
node 檢查.mjs            # 33 條：真的開瀏覽器點過一遍
```

`測試.mjs` 驗餘額、月結、分類統計、下次扣款、金額與日期格式化，
還有示範資料本身的一致性（帳目不能指到不存在的帳戶或分類）。
算錯了不會有任何地方報錯，只會安靜地給一個錯的數字，所以這些一定要測。

`檢查.mjs` 開一個 headless Chrome，把每個對話框、每個按鈕點過一遍，
**跑在臨時資料夾上**，每次從全空開始——因為真正會被踩到的 bug
（取消鍵按不動、預算打開是空的、頂欄塌掉）都是算術測試抓不到、
而且只在「全新使用者」的狀態下才出現的。
